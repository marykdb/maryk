title: CLI
description: Interactive terminal client for browsing and editing Maryk stores.
---

Maryk ships with an interactive CLI for exploring data models and records. It connects to RocksDB and FoundationDB stores and provides scrolling viewers for `get` and `scan`.

## Run

From the repo root:

```bash
./gradlew :cli:runJvm
```

Release-native CLI tasks are host-specific:

```bash
# macOS Apple Silicon
./gradlew :cli:runReleaseExecutableMacosArm64

# Linux x64
./gradlew :cli:runReleaseExecutableLinuxX64
```

Use `:cli:runJvm` on other hosts. Native CLI release binaries currently target
macOS and Linux; this is not a generic command for every platform.

## Connect

```text
connect rocksdb --dir /path/to/rocksdb
connect foundationdb --dir maryk/app/store [--cluster /path/to/fdb.cluster]
```

## Serve

Expose a local store over HTTP:

```text
serve rocksdb --dir ./data --host 127.0.0.1 --port 8210
serve foundationdb --dir maryk/app/store --cluster /path/to/fdb.cluster --port 8210
serve rocksdb --dir ./data --host 127.0.0.1 --bearer-token-file ./maryk-token
```

You can also pass `--config` with key/value config. See [CLI commands](./commands/) for details.

Prefer `--bearer-token-env`, `--bearer-token-file` or `--bearer-token-stdin`.
The compatibility `--bearer-token` option warns because process arguments may
expose the secret. Interactive commands do not expand shell variables.

Loopback serving needs no authentication. Non-loopback plaintext binds require the explicit unsafe
`--allow-insecure-remote-binding` opt-in even with bearer authentication.
Bearer authentication does not encrypt traffic; use TLS termination or SSH
tunneling outside localhost.

## Browse

| Command | Action |
| --- | --- |
| `list` | Show data models. |
| `model <name\|id>` | Print the schema. |
| `get <model> <key>` | Open a record viewer. |
| `scan <model> [options]` | Open a scrollable list; use `show` and `filter` to shape the list. |

Example session:

```text
connect rocksdb --dir ./data
list
scan Client --show info.name.firstNames,info.name.familyName --order -info.name.familyName
```

## Edit

Inside the `get` viewer, use `set`, `unset`, `append`, `remove`, `save`, and `load` to change values. If the viewer was opened from `scan`, the `close` command returns to the scan list.

Inline values are parsed as Maryk YAML scalars; quote strings with spaces or YAML special characters.

## Scan options

| Option | Effect |
| --- | --- |
| `--start-key <base64>` | Start scanning from this key. |
| `--limit <n>` | Page size per fetch (default 100). |
| `--include-start` / `--exclude-start` | Include the start key (default), or exclude it. |
| `--to-version <n>` | Scan as of a version. |
| `--include-deleted` | Include soft-deleted records. |
| `--where <expr>` | Filter expression in Maryk YAML. |
| `--order <ref,...>` | Order by references; prefix with `-` for descending order. |
| `--select <ref,...>` | Fetch only these fields. |
| `--show <ref,...>` | Show these fields first. |
| `--max-chars <n>` | Maximum characters per row (default 160). |

For large datasets, prefer `--order` on an indexed property or add filters to keep scans efficient.

## SQL

Use `sql SELECT ...` for bounded reports, and `sql --write ...` for serializable
mutations. An interactive connection retains `sql --write BEGIN`, subsequent
queries and writes, savepoints, and `sql --write COMMIT` or `sql --write ROLLBACK`.
Use `sql --resolve-commit` when a submitted commit is uncertain. One-shot mode
supports queries and autocommit writes but cannot retain an interactive transaction.
See the [SQL guide](../querying/sql/) and [command reference](./commands/).
